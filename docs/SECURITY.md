# Security and secret handling

## Repository rules

Never commit:

- `.env` files, API tokens, passwords, private keys, or customer license files.
- SQLite/database files, database dumps, production configuration, or logs.
- A customer's printer address. Printer addresses are entered by the customer in the GLPI setup page and stored in the local service configuration.

`.gitignore` and the release builder exclude common secret and database file names. The release builder refuses to overwrite an existing `dist/` folder and copies only the application packages. Review the source and release archive before publishing any build.

## Credentials and licensing keys

- The service installer generates a fresh random API token on the target host. It is stored in `/etc/zebrashipping/print-service.env`, never in this repository.
- The GLPI Apache environment receives the same token. Keep its Apache configuration readable only by root; do not paste the token into an issue, chat, or Git remote.
- The Ed25519 private signing key is generated by the operator and encrypted with a passphrase. Keep it outside the product repository and customer server. The public key may be configured in the Print Service.
- The administrator recovery export contains only the customer's activation license and installation identity. It never contains the Ed25519 private signing key; store the export securely.
- License signing and key-generation utilities are excluded from customer release archives.

## Network boundaries

- Print Service listens on loopback only.
- Printer endpoints are configured by an administrator and must resolve to private network addresses. Print requests select a registered printer ID; they cannot supply a host or port.
- The service authenticates every management and print request with a bearer token of at least 32 characters.

## State and customer data

- The service creates a new local SQLite database for trial state and job metadata; it does not import a GLPI database.
- GLPI stores shipping destination/contact fields and job history in its own new plugin table.
- The service's SQLite database, printer configuration, license files, and generated keys are deployment data and must not be copied into the product source archive.
- Professional users can save administrator-supplied ZPL templates. The service independently enforces the Professional license, limits template size, validates placeholders, and strips ZPL command markers/control characters from substituted GLPI values. Custom ZPL commands are intentionally passed through to the configured printer; only trusted administrators should edit a template, and they should validate it on their printer.
- The GLPI recovery export does not replace a full backup: printer settings, API tokens, job history, and Print Service trial state remain in their respective GLPI or service data stores.
